  What changed

  contacts.py (it was empty before) now has one function for each of the four
  operations:
  - add_contact: the name is required and can't be blank. If you run it with no
    arguments, it asks for the name. Phone, email and country are optional.
  - update_contact: finds the contact by its whole name, ignoring case. It can
    change the name, phone, email or country. A blank value like --country ""
    removes that field.
  - delete_contact: finds the contact by its whole name and asks for
    confirmation unless you pass --yes.
  - search_contacts and list_contacts: --search matches part of a field and
    ignores case. It works with --name, --phone, --email or --country.

  How the rules in rules.md are enforced:
  - Unique names: names are compared ignoring case and surrounding spaces.
  - Email: it must look like name@example.com.
  - Phone: 7 to 15 digits, with an optional leading +. Extensions like x123 are
    rejected.
  - No combining: --list, --search, --update and --delete can't be used
    together.
  - Backup: each save first copies the book to contact_book.json.bak. If the
    write fails, the backup is restored.
  - Empty file: contact_book.json is currently empty, and that is treated as an
    empty contact book.

  Where conventions.md and rules.md disagreed

  - Duplicate names: conventions.md says to ask whether to add a number to the
    new contact's name, while rules.md says to reject it. The program asks:
    "yes" saves it as "Jane Doe 2", and anything else rejects it.
  - Email search example: --search --email "555-9999" has a comment about names
    containing "978", which doesn't match. I made --search accept any of the
    fields rather than guess which one was meant.
